# Design plans — Doory mobile

Phased implementation for the Flutter buyer app. The sequence mirrors the web storefront branches on [Doory-Store/frontend](https://github.com/Doory-Store/frontend):

| Phase | Web branch | Plan |
| --- | --- | --- |
| 0 | `cursor/phase-0-api-foundation-876e` | [phase-0-api-foundation.md](./phase-0-api-foundation.md) |
| 1 | `cursor/phase-1-home-categories-43d4` | [phase-1-home-categories.md](./phase-1-home-categories.md) |
| 2 | `cursor/phase-2-live-product-page-8ef2` | [phase-2-live-product-page.md](./phase-2-live-product-page.md) |
| 3 | `cursor/phase-3-listing-search-e983` | [phase-3-listing-search.md](./phase-3-listing-search.md) |
| 4 | Planned on web (`storeHref` in `lib/links.ts`) | [phase-4-store.md](./phase-4-store.md) |
| Later | Not built on web yet | [phase-later-cart-checkout-orders.md](./phase-later-cart-checkout-orders.md) |

Read `../PRODUCT.md` and `../DESIGN.md` before starting a phase. Do not skip phase 0. Do not pull later-phase features forward in order to fill a screen.

Web-only design-plans (header mega menu, desktop shelf density, and the Trendyol module studies under `design-plans/` in the frontend repo) stay there. This folder records the **mobile** plan, not a copy of those desktop studies.
