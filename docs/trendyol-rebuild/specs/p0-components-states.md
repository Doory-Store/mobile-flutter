# P0 · حالات الشاشة

يغطي [#10](https://github.com/Doory-Store/mobile-flutter/issues/10). المراجع: `ref/50-cart-empty.jpg`، `ref/72-orders.jpg`، `ref/74-addresses.jpg`. المكوّنات الثلاثة تُستعمل في كل المراحل، والنص يأتي من الشاشة لا من داخل المكوّن.

## EmptyState

عمود في وسط المساحة المتاحة. المرجع دائرة 64 dp بخلفية `#FFF3E8` ثم عنوان ثم رسالة ثم زر.

### التشريح

| الجزء | المقاس | الرمز |
|---|---|---|
| الدائرة | 64 dp | تعبئة `primarySubtle` |
| الأيقونة | 32 dp، outlined | `primary` |
| فراغ | 16 dp | — |
| العنوان | `toolbarTitle`، وسط، سطران كحد أقصى | `textPrimary` |
| فراغ | 8 dp | — |
| الرسالة | `bodySecondary`، وسط، عرض الشاشة ناقص 64 | `textSecondary` |
| فراغ | 24 dp | — |
| الزر | `DooryButton` هيئة `primary` وحجم `h45`، عرضه عرض الأب ناقص 32 (16 من كل جانب) | يظهر عندما `actionLabel` غير فارغ |

فوق الدائرة حشو 40 dp عن المحتوى السابق إن وُجد، حتى لا تلتصق الدائرة بشريط العنوان. المحتوى المقترح (رف «منتجات مقترحة») يضعه الأب تحت الحالة، لا داخلها. بانر الكوبونات في سلة ترينديول غير موجود.

### الحالات

| الحالة | الرسم |
|---|---|
| default | الدائرة والعنوان والرسالة والزر |
| no action | الزر محذوف |
| pressed على الزر | حالة `DooryButton` |
| large text | الرسالة تلتف، والزر يبقى بعرضه، والصفحة تتمرر إن طال العمود |

أمثلة نص تملكها الشاشات لاحقاً، والمكوّن لا يثبّتها:

| الشاشة | العنوان | الرسالة | الزر |
|---|---|---|---|
| السلة | «سلة مشترياتك» | النص الذي تكتبه شاشة السلة في P7 | «متابعة التسوق» |
| الطلبات | عنوان تكتبه شاشة P10 | رسالة الفراغ الخاصة بالطلبات | «ابدأ التسوق» |
| تبويب P0 الفارغ | اسم التبويب | «هذا القسم جاهز للعرض، ومحتواه يصل مع مرحلته.» | بلا زر |

### RTL والوصول

العمود في الوسط والنص في الوسط. الأيقونة لا تُقلب إلا إذا كانت سهماً، وأيقونات الفراغ (سلة، صندوق، قلب، دبوس) لا تُقلب.

العنوان `header`. المجموعة تُعلن مرة عند الظهور. الزر تسميته نصه.

### الخصائص

| الخاصية | النوع | الافتراضي | الدور |
|---|---|---|---|
| `icon` | IconData | — | داخل الدائرة |
| `title` | String | — | العنوان |
| `message` | String | — | الرسالة |
| `actionLabel` | String أو null | null | نص الزر |
| `onAction` | callback | — | الضغط |

## ErrorState

البنية نفسها حتى يتعرّف المتسوّق على نمط واحد. الفرق في لون الأيقونة ونص إعادة المحاولة.

### التشريح

| الجزء | القيمة |
|---|---|
| الدائرة | 64 dp، تعبئة `surfaceSubtle` |
| الأيقونة | `error_outline` بحجم 32، لون `danger` |
| العنوان الافتراضي المقترح | «تعذّر التحميل» |
| الرسالة | تفسّر ما حدث وما يمكن فعله، بلا لوم |
| الزر | «إعادة المحاولة»، `primary` / `h45` |

السحب للتحديث يبقى على الشاشة الأم بالإضافة إلى الزر. الزر هو المسار الواضح.

### الحالات

| الحالة | السلوك |
|---|---|
| default | الرسم أعلاه |
| pressed | حالة الزر |
| retrying | الزر `loading`، والعنوان يبقى، حتى لا يقفز التخطيط |
| offline مع محتوى سابق | هذه الحالة للشاشة: تبقي المحتوى وتظهر شريطاً رفيعاً. `ErrorState` يملأ الصفحة عندما لا يوجد محتوى لعرضه |

### RTL والوصول

مثل `EmptyState`. عند الظهور تُعلن الرسالة كمنطقة حيّة حتى يسمعها قارئ الشاشة بعد فشل التحميل. الزر «إعادة المحاولة».

### الخصائص

| الخاصية | النوع | الافتراضي | الدور |
|---|---|---|---|
| `title` | String | «تعذّر التحميل» | العنوان |
| `message` | String | — | التفاصيل |
| `onRetry` | callback | — | إعادة المحاولة |
| `retrying` | bool | false | زر التحميل |

## SkeletonBox

مستطيل بلون `surfaceSubtle` يطابق شكل المحتوى القادم. لا وميض يغيّر المقاس.

### التشريح

| الجزء | القيمة |
|---|---|
| اللون الثابت | `surfaceSubtle` |
| الوميض | تدرّج يمر من `surfaceSubtle` إلى `surface` ثم يعود، المدة `shimmer` |
| نصف القطر | خاصية، افتراضها `radius8` |
| الحركة المخفّضة | لون ثابت بلا تدرّج عند `disableAnimations` |

الهيكل يحجز الارتفاع النهائي حتى لا يقفز المحتوى عند الوصول.

### أشكال جاهزة

| الاسم | الشكل |
|---|---|
| `SkeletonBox` | مستطيل بالمقاس ونصف القطر المعطيين |
| `SkeletonText` | ارتفاع 12 dp، نصف قطر 4، وعرض نسبة من الأب (1 أو 0.6) |
| `SkeletonProductCard` | بئر 2:3 بنصف قطر 0، ثم سطر بعرض كامل، ثم سطر بعرض 0.6، ثم سطر سعر بعرض 0.4. الحشو 8. العرض 193.5 في العمود أو 137 في الرف |
| `SkeletonListRow` | ارتفاع 56، ومستطيل نص بعرض 40٪ محاذى للبداية، وحشو أفقي 16 |
| `SkeletonSortRow` | ارتفاع 49، دائرة 22 على البداية بعد حشو 14، ثم سطر نص بعرض 40٪. بلا فواصل. لصف `radio-leading` |
| `SkeletonChip` | 72×30، نصف قطر pill |

شبكة التحميل في القائمة: ستة `SkeletonProductCard` في عمودين بالفراغات 8 dp. رف التحميل: ثلاثة بطاقات عرض 137.

### الحالات

| الحالة | الرسم |
|---|---|
| loading | الوميض أو اللون الثابت |
| reduced motion | لون ثابت |
| replaced | الأب يبدّل الهيكل بالمحتوى عند `ok`، أو بـ `ErrorState` عند الخطأ، أو بـ `EmptyState` عند الفراغ |

### الوصول

الحاوية `Semantics` «جارٍ التحميل» مع حالة `busy`. الأبناء مخفيون عن قارئ الشاشة حتى لا تُقرأ مستطيلات فارغة.

### خصائص `SkeletonBox`

| الخاصية | النوع | الافتراضي | الدور |
|---|---|---|---|
| `width` | double أو null | عرض الأب | العرض |
| `height` | double | — | الارتفاع |
| `radius` | double | 8 | نصف القطر |

## DemoLabel

علامة البيانات التجريبية. النص الثابت «بيانات تجريبية» من `DooryStrings.demo`.

### التشريح

| الجزء | القيمة |
|---|---|
| النص | `captionStrong` بلون `textPrimary` |
| الحشو | 8 أفقي، 2 شاقولي |
| التعبئة | `primarySubtle` |
| نصف القطر | pill |
| الموضع | تحت السعر في البطاقة، أو في رأس شاشة تعتمد fixture |

تظهر عندما `sample == true` فقط. محتوى حي بلا هذه العلامة. لا علامة على صورة المنتج نفسها حتى تبقى الصورة نظيفة، والنص هو الذي يعلن المصدر.

### الوصول

النص قابل للقراءة، وهو جزء من تسمية البطاقة بعد السعر: «بيانات تجريبية».

### الخصائص

لا خصائص نصية. المكوّن ثابت حتى لا تتعدد صيغ الجملة. الإظهار والإخفاء قرار الأب.

## ترتيب الحالات في الشاشة

1. التحميل الأول: هياكل تطابق التخطيط، والسحب للتحديث متوقف أو يعمل بلا قفزة.
2. نجاح بقائمة: المحتوى، والسحب يعيد التحميل.
3. نجاح بفراغ: `EmptyState`.
4. فشل بلا محتوى: `ErrorState`.
5. فشل مع محتوى ظاهر: المحتوى يبقى، ورسالة قصيرة مع «إعادة المحاولة».
6. بيانات fixture: المحتوى نفسه مع `DemoLabel`.
